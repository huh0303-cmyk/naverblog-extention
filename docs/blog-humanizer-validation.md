## 구현

- `packages/blog-humanizer`: 외부 의존성이 없는 Node.js 공통 모듈. 모델 호출은 `complete` 함수로 주입한다. Electron·네이버·특정 사용자 경로에 의존하지 않는다.
- `SKILL.md`와 앱이 같은 `references/blog-rules.md`를 사용한다. 원본 im-not-ai의 한국어 표현·의미 보존 지침을 참고했고 MIT 원문과 출처를 포함했다. 통계 기준, 점수표, 보고서 출력, Python 실행기, 다중 검토 루프는 가져오지 않았다.
- 실제 앱 순서는 Writer → Humanizer → Main → Image이다. Writer 결과는 윤문 시작 때 바로 미리보기에 표시한다.
- 휴머나이저는 변경할 블록만 반환한다. 제목·섹션·이미지 표식·참고자료는 원래 위치 그대로 조립한다. 숫자·직접 인용·URL·목록과 보호 용어는 기계적으로 확인한다.
- 의미 판단을 정규식으로 구현하지 않았다. Main은 최종 본문 및 변경 문단의 원문을 함께 받아 의미·조건·부정·사실을 확인한다.
- 신규 입력당 모델 작업 1회, 내부 자동 재시도 없음. 같은 입력과 이미 윤문한 결과는 작업 캐시로 재사용한다. 문장 다듬기 실패는 원고를 보존하고 전체 주제 재탐색을 중지한다.
- 기존 Codex 업데이트로 삭제된 관리 경로를 발견해, 해당 관리 경로에 한해서 현재 설치 실행 파일을 다시 찾도록 보완했다. 사용자 지정 경로는 바꾸지 않는다.

## 시험 중 발견해 보완한 문제

첫 실행(`2026-09-27T23-57-46-630Z`)에서는 같은 의미의 어순 변경과 휴관을 '피한다'에서 '확인한다'로 바꾸는 지침 약화가 있었다. 이를 성공 사례로 채택하지 않았다.

두 번째 실행(`2026-09-28T00-00-43-736Z`)에서는 정책 글의 부분 부정이 전체 부정으로 바뀌는 문장이 있었다. 단순 동의어 교체, 행동 지침 약화, 부분 부정·의무 강도 변경을 피하도록 규칙을 보완했다. 최종 실행의 변경 문단을 전부 대조한 결과 이 문제들이 재발하지 않았다.

세 실행 모두 실제 모델 호출이며, 실패한 초기 결과도 별도 테스트 폴더에 보존했다. 첫 두 실행의 보존 문제 때문에 최종 검증을 별도로 수행했다. 이는 프로그램이 원고마다 세 번 윤문하도록 설계되었다는 뜻이 아니다.

## 추가 서브에이전트 교차검증 및 0.1.1 수정

사용자 요청에 따라 실제 윤문 4건을 한 차례 더 실행했다. 코드 검토 담당과 문체 검토 담당 서브에이전트가 독립 검토했고, 주 에이전트가 결과를 직접 대조했다.

실행 폴더: `runtime/humanizer-tests/2026-09-28T00-10-26-086Z/`

이 재시험에서는 자연스러운 대조 글은 유지됐지만, 정책 글에 부분 부정의 범위를 바꿀 여지가 있는 수정이, 여행 글에 행동 지침을 약화하는 수정이 다시 나왔다. 따라서 앞선 한 번의 결과만으로 보존 지침이 항상 지켜진다고 판단할 수 없었다. 실제 기존 Main 검증도 여행 문장을 허용했으므로 단순히 프롬프트 예시만 더 붙이는 방식으로 처리하지 않았다.

수정 사항:

1. 반려된 윤문 캐시가 Writer의 원문 복원을 다시 취소하는 결함을 재현했다. 검수 피드백을 다음 윤문 요청과 캐시 키에 반영했다. 같은 원고라도 검수 조건이 바뀌면 새 검토가 필요하며, 조건이 같을 때만 재사용한다.
2. 이미 윤문한 결과를 재사용할 때 원본·수정 이력이 사라지던 부분을 수정했다. 캐시에서도 원본에서 결과를 다시 조립해 일치 여부를 확인하고 전후 증거를 Main에 유지한다.
3. Main이 변경별 `keep`/`restore`를 결정하도록 했다. 의미가 달리 읽힐 여지가 있거나 단순 취향 변경이면 원문 복원을 선택한다. 코어는 문장 뜻을 판단하지 않고 ID로 연결된 원문을 복원한다. 복원만으로 해결되면 Writer 재호출 없이 승인 미리보기와 이미지 단계로 이어진다. 원문 자체의 오류는 별도로 기존 사실 검증을 받아야 한다.
4. 코드 검토에서 Main의 최종 출력 스키마에도 결정 필드가 있어야 한다는 누락을 찾아 일치시켰다. 결정이 누락·중복되거나 원고가 달라지면 발행 전에 중지한다.

같은 원고 두 편에 실제 Main 검증을 추가로 실행하고 복원본을 두 에이전트와 주 에이전트가 대조했다.
