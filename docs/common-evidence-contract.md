# 공통 근거 처리 계약

코어는 카테고리 이름으로 근거의 신뢰성이나 글의 의미를 판단하지 않는다.

1. 조사 에이전트가 독자의 질문에 필요한 주장과 근거를 판단한다. 추가 자료가 필요하면 기존 검색 예산 안에서 검색어를 반환한다.
2. 이미 제공된 문서에서 다른 구간이 필요하면 `evidenceRequests`를 선택적으로 반환한다.
3. 코어는 URL과 문자 위치를 확인해 원문 일부를 재사용한다. 일치하지 않거나 위치가 중복되어 모호하면 같은 검색 예산 안에서 기존 검색으로 처리한다.
4. 에이전트가 발췌의 출처·적용 범위·예외·시점을 판단한다. 원문 위치를 찾았다는 사실은 주장을 입증했다는 뜻이 아니다.
5. 기존 한 번의 메인 검수에서 `meaningChecks`로 원고와 원문의 의미를 대조한다. 별도 분야별 검수 단계는 없다.

## 위치 요청

```json
{
  "verificationQueries": ["문서의 변경 조건"],
  "evidenceRequests": [{
    "query": "문서의 변경 조건",
    "sourceUrl": "https://example.com/document?id=1",
    "anchors": [{"start": "변경 조건", "end": "접수 방법"}]
  }]
}
```

`query`는 실행할 검증 검색어와 일치해야 한다. `sourceUrl`은 기존 원문의 URL이며 버전·문서 ID를 보존한다. `start`와 선택적 `end`는 에이전트가 지정한 원문의 실제 문구다. 코어는 문구가 법령의 조문인지, 제품 설명서의 절인지, 방송 리뷰의 소제목인지 구별하지 않는다. 끝 문구가 없으면 시작 위치부터 제한된 길이를 전달하고 부분 발췌임을 표시한다. 동일 문서의 여러 요청 구간은 함께 전달하며 문서당 3,000자 한도를 유지한다.

## 공통 의미 검수

`meaningChecks: [{articleQuote, sourceQuote, meaningPreserved}]`에 의미 변화 위험이 있는 실제 문장만 최대 3개 기록한다. 해당 문장이 없으면 빈 배열이다. 주체·대상·조건·시점·부정·인과·의무·가능성을 확인하고, 의미가 달라지면 기존 수정 단계에서 해당 부분만 고친다. 원고 자체를 코어의 문장 치환 규칙으로 고치지 않는다.

사용자가 출처 검증 생략을 선택하면 외부 신뢰성 검증과 위치 기반 검증 검색을 생략한다. 주어진 자료의 내용을 바꾸지 않는지에 대한 검수는 유지한다.

## 변경 범위

- 법령명/조문 번호를 파싱해 캐시를 찾던 코어 제거.
- 법률 전용 프롬프트·분야 분류 출력·`legalRelations` 제거.
- 문서·구간 지정과 의미 보존의 공통 계약으로 교체.
- 휴머나이저의 분야별 문체 지침을 공통 의미 보존 지침으로 통합.
- HTML·PDF·HWP 판독, 사이트별 원문 페이지 접근 처리는 문서 형식 처리이므로 유지. 출처의 옳고 그름을 판정하는 분야별 예외와는 별개다.
- 기존 결과와 체크포인트는 형식이 추가됐다는 이유로 무효화하거나 재생성하지 않는다. 기존 문자열 검색어도 계속 지원한다.

이번 검증은 회귀 테스트이며 추가 유료 생성·이미지·발행·앱 재시작·배포 빌드를 수행하지 않았다.
