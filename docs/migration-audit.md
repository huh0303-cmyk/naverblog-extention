## 선행 수정

| 점검 요청 | 발견한 문제 | 반영한 변경 |
| --- | --- | --- |
| 불필요한 토큰 | 연구 이후 별도 작성 계약 정제, 사용량 조회용 `Return exactly OK` 호출, 실패 유형과 무관한 xhigh 재실행 | 계약을 연구 출력에 통합, 사용량은 로컬 기록만 조회, effort 미지원 오류만 제한적으로 재시도 |
| 지나치게 강한 검사 | 태그 필수, 섹션마다 이미지 필수, 이미지 마커 위치·소제목 완전 일치, 여러 편집 품질 플래그 | 제목·본문 존재와 이미지 번호 연결 등 형식 검사 유지. 태그·섹션별 이미지 강제 제거. 사실성과 주제 충족 여부는 모델 검수 |
| 이중·삼중 검증 | 연구 보강·본문 재작성·외부 자동 재시도가 중첩. 실패 대상은 반복 주기 없이 다음 순회 가능 | 연구 최대 3회, 본문 최대 2회, 각 원고 버전 최종 검수 1회. 새 원문이 없으면 연구 재호출 중단. 실패 순회도 설정된 반복 주기 준수 |

| 사실성 범위 | 도메인·검색 후보 점수 중심의 출처 실패 판단, 최종 검수의 연구 요약 의존 | 원문 발췌·출처 ID·필수 주장 연결을 전달. 필수 주장에 근거 없으면 중단하되 부차적 미확인 정보는 생략 가능. 단일 직접 원문과 새로운 도메인도 허용 |

| 반복 로그 | 동일 단계 로그와 화면 로그 무제한 누적 | 작업별 단계 메시지 중복 제거, 화면별 최근 300행 및 연속 메시지 억제 |

상한은 앱의 모델 **작업 호출** 기준입니다. 실제 토큰 비용은 모델의 출력, 도구 사용, 검색 자료 길이에 따라 달라집니다. 실제 유료 생성 비교 실험을 수행하지 않았으므로 절감률을 제시하지 않습니다.

## 브라우저 구조

- 앱 → OS의 일반 Chrome 실행 → 사용자가 네이버 로그인 → 확장 연결 → 대상 글쓰기 화면 확인.
- 계정별 로컬 데이터 폴더를 사용하고 Google 로그인/동기화와 매칭하지 않습니다.
- Chromium 자동화 라이브러리 및 제어 포트를 제거했습니다. 확장도 cookies/debugger 권한이 없습니다.
- localhost API는 127.0.0.1만 바인딩하고 Host·Origin·연결 토큰을 확인합니다. 코드 만료와 연결 시도 횟수를 제한합니다.
- 계정별 작업과 이미지 접근을 분리했습니다. 같은 Chrome 저장 공간을 두 계정에 연결하는 실수를 거부합니다.
- 로그인 대기는 시간 제한 없이 유지하고 사용자가 취소할 수 있습니다. 작성·최종 발행 단계는 기록하며 앱 재시작 때 자동 재전송하지 않습니다.
- 실제 발행 URL을 확인하지 못한 작업은 성공으로 표시하지 않습니다. 결과가 불확실한 동일 원고를 자동 재발행하지 않습니다.

## 검증

- `npm run check`: JavaScript 문법과 확장 파일·Manifest 검사.
- `npm test`: 계정 격리, 연결 토큰, 로그인 대기, 취소, 재시작, 이미지 접근, 중복 발행 방지, 생성 호출 횟수, 근거 연결, 과도한 이미지 검증 제거, 실패 순회의 대기 등 22개 테스트 통과.
- Electron 화면 검사: 실제 앱 IPC, 다크 기본값, 라이트 전환, 본문 폭 951px/높이 452px 확인. 결과는 로컬 `artifacts/ui-dark.png`, `artifacts/ui-light.png`.
- 오프라인 편집기 검사: 실제 Chromium의 contenteditable 입력, 인용구 버튼 동작, 문단 순서, 누락 감지 확인. 네이버 서버를 사용하는 E2E 발행 테스트와는 구분합니다.
- Windows portable 실행 파일 빌드 완료. 패키지 내부 18개 앱 파일과 확장 파일이 최종 소스와 일치함을 확인했습니다.
- npm 의존성 검사: 설치 당시 알려진 취약점 0건.
- Windows 일반 Chrome 수동 로그인·확장 연결: 사용자 제공 블로그에서 대기 → 세션 유효 전환 확인. 글쓰기 권한 확인 결과 valid, navigator.webdriver=false, 기존 원고 없음. 앱 재시작 후 세션 확인을 다시 요청하여 재로그인 없이 valid 응답도 확인했습니다. 글 입력/발행은 테스트 범위에서 제외.

실제 네이버 인용구·이미지·공개/예약 발행, 실모델 생성 전체 과정, macOS는 아직 실환경 검증하지 않았습니다. 네이버 편집기 변경이나 합성 DOM 입력 미수용은 실제 사이트에서 추가 확인이 필요합니다. DOM 반영 검사 실패 시 원고를 남기고 발행을 중지합니다.

## 기존 기능 영향

초기 전환에서는 티스토리의 기존 Playwright 코드를 제거하고 발행을 비활성화했습니다. 이후 2026-09-27 확장 0.3.0에서 티스토리 어댑터를 추가했습니다. 하나의 티스토리 로그인과 네이버 계정별 선택적 Blog ID를 사용하며, 네이버 완료 후 티스토리 실패 시 완료된 네이버 발행은 다시 실행하지 않습니다. Windows Chrome에서 기존 원고·이미지로 확장을 통한 비공개 발행과 완료 URL 수신을 검증했습니다. macOS 실행 도우미는 별도 실기 검증이 필요합니다.

기존 계정·카테고리·작업 폴더는 `BLOGAUTO_RUNTIME_ROOT`로 지정할 수 있습니다. 기존 자동화 Chrome 폴더를 새 계정 폴더로 복사하지 않으며 최초 로그인과 개발자 모드 설치는 다시 필요합니다.
